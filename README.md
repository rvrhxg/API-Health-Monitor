# API Health Monitor

Отдельная учебная Python-утилита для разовой диагностики HTTP-сервисов. Python 3.12+, без сторонних runtime-зависимостей. Это MVP, не полноценная система мониторинга.

## Запуск

```sh
python health_monitor.py --url http://127.0.0.1:8000/api/health --timeout 3 --retries 2 --csv report.csv
python health_monitor.py --demo --csv demo.csv
python -m pip install pytest==8.4.2
python -m pytest -q
```

Можно указать несколько `--url` (до 100), проверка последовательная. Используйте только разрешённые вам сервисы. Вывод stdout — JSON Lines; stderr — безопасная ошибка конфигурации. Код возврата: 0 — все цели доступны; 1 — хотя бы одна недоступна; 2 — неверные параметры или ошибка записи отчёта. В demo ожидается код 1: один сервис намеренно неисправен.

## Как работает

HTTP GET, успех — статус 200–299. Redirect не выполняется и не считается успехом. Тело ответа не читается. Каждая попытка измеряется monotonic-clock до получения заголовков; response_ms — последняя попытка, total_ms — вся проверка с паузами. Результат содержит UTC checked_at, статус, класс ошибки и число попыток. TLS-сертификаты проверяются стандартным клиентом; проверка не отключается.

Повторы: timeout, connection_error, HTTP 429/500/502/503/504. Остальные HTTP-ответы возвращаются сразу. `--retries 2` означает до трёх попыток; ограничение 0–5. Паузы экспоненциальные от 0.2 секунды с ограничением 5 секунд. Retry-After не обрабатывается. Timeout 0–60 секунд (строго больше нуля) относится к сетевым операциям стандартного urllib, а не к общему дедлайну: DNS/несколько сетевых операций могут увеличить полную длительность.

JSON-логи содержат только service-N, попытку, статус и длительность. URL, query, заголовки, тело ответа и сообщения исключений не записываются. Не передавайте секреты в аргументах командной строки: они могут быть видимы в истории оболочки/списке процессов. Credentials в URL отклоняются. CSV содержит одну строку на итоговую проверку; метки защищены от интерпретации как формулы. Указанный CSV перезаписывается.

## Демонстрация диагностики

`--demo` запускает временный HTTP-сервер только на loopback со случайным портом и тремя вымышленными целями:

- fictional-healthy: 200 с первой попытки;
- fictional-recovering: 503, затем 200 после повтора;
- fictional-outage: 503 на обеих попытках, итог недоступен.

Диагностика: http_status/503 означает, что HTTP-сервер ответил, но заявил недоступность; timeout означает отсутствие ответа в пределах сетевого ожидания; connection_error — ошибка подключения/DNS/TLS. Причина сбоя бизнес-логики из одной HTTP-пробы не устанавливается. После сценария сервер закрывается. Внешних запросов и клиентских данных нет.

## Тесты и ограничения

pytest: mock transport и HTTP opener, точные длительности, retry/backoff, исчерпание тайм-аутов, HTTP-статусы, валидация, редактирование логов, CSV и loopback-демо. CI настроен на Python 3.12/3.13/3.14. Это отдельная утилита, существующие приложения не импортируются и не изменяются.

Нет планировщика, фонового сервиса, уведомлений, SLA-истории, авторизации целей или параллельных проверок. Доступность endpoint не доказывает исправность всех зависимостей. HTTP-запросы выполняются от имени локального пользователя; это не API для приёма непроверенных URL от внешних пользователей. Зависимости тестов устанавливаются отдельно, библиотека для выполнения не требуется.
